# Message Deletion Manager - User Guide

> **Just need the basics?** Check out the [Quick Start guide](user-quick-start.md) for essential instructions.

## What This Tool Is For

The Message Deletion Manager helps you remove messages that contain mistakes or information that shouldn't be in our workspace. This includes:

- **Personal or sensitive information** that was accidentally shared (phone numbers, addresses, internal IDs, etc.)
- **Incorrect information** that could mislead others (wrong dates, incorrect data, outdated details)
- **Accidental postings** (messages sent to the wrong channel, duplicates, or drafts sent by mistake)
- **Typos or errors** in important announcements or documentation

## What This Tool Is NOT For

This tool is designed to correct genuine mistakes, not to erase history or avoid accountability. **Do not use this tool to:**

- Remove inflammatory or inappropriate comments after the fact
- Erase conversations to avoid accountability for what was said
- Delete critical feedback or constructive criticism
- Revise history by removing past statements or decisions
- Hide mistakes that others need to learn from

**Important:** Every deletion request is reviewed by an administrator and permanently logged in our audit system. All deletion activity remains on record, including who requested it, what was deleted, and when.

## How It Works

### The Approval Process

1. **You request deletion** of your own message
2. **Admins review** your request and see the full context
3. **Decision is made** - admins either approve or deny based on the legitimacy of the request
4. **You're notified** of the decision automatically
5. **Action is logged** - all deletions are permanently recorded for compliance and oversight

### Step-by-Step Instructions

#### Requesting Message Deletion

1. Find the message you want to delete (it must be a message you posted)
2. Right-click on the message (or click the three dots menu on mobile)
3. Select **"Delete my message"** from the shortcuts menu
4. You'll receive a confirmation that your request has been submitted

#### What Happens Next

- Admins will see your deletion request in a private review channel
- They'll see:
  - Who's requesting the deletion (you)
  - What channel the message is in
  - A preview of the message content
  - A link to view the original message
- An admin will review and either approve or deny the request
- You'll receive a direct message with the decision

#### Approval Outcomes

**If Approved:**
- The message is deleted immediately
- You receive a confirmation message
- The deletion is logged in our audit system

**If Denied:**
- The message remains in the channel
- You receive a notification of the denial
- You can contact an admin directly if you believe the denial was in error

## Important Restrictions

### You Can Only Delete Your Own Messages

The tool will only allow you to request deletion of messages that you posted. If you try to delete someone else's message, you'll receive an error.

### Admin Approval Is Required

All deletion requests require approval from a workspace administrator. This ensures that:
- Deletions are legitimate and appropriate
- There's oversight on what's being removed
- The tool isn't misused for historical revision
- Important context isn't lost unnecessarily

### Complete Audit Trail

Every deletion request and action is permanently logged, including:
- What was deleted
- Who requested it
- Who approved or denied it
- When it happened

This audit trail exists for:
- Compliance and regulatory requirements
- Transparency and accountability
- Quality control and oversight
- Potential future reference

### Technical Limitations

- **Channel membership required:** The **MAF Admin user must be in the channel** (public or private) for deletions to work. If deletion fails due to this, you'll need to:
  - For public channels: Invite or add MAF Admin to the channel
  - For private channels: Add MAF Admin as a member
- **Privacy consideration:** When you add the Message Deletion Manager bot to a private channel, it gains access to see all data and messages in that channel, not just the ones you want to delete.
- **Message age:** Whilst there's no hard time limit, very old messages may have archival or compliance implications that could affect approval.
- **Already deleted:** If a message was already deleted by other means, the deletion request will fail.

## Expected Response Times

Response times depend on admin availability:
- Most requests are reviewed within business hours
- Urgent requests (e.g., leaked sensitive information) should be flagged to an admin directly via direct message in addition to using this tool
- Non-urgent requests may take longer during weekends or holidays

## When to Contact an Admin Directly

Use direct messaging to contact an admin if:
- You've accidentally shared sensitive credentials or security information (use this tool AND contact an admin immediately)
- Your deletion request was denied and you believe it was a mistake
- You need help understanding whether a deletion request is appropriate
- The technical deletion process fails

## Best Practices

### Think Before Posting

The best way to avoid needing deletions is to:
- Review messages before sending, especially in public channels
- Use private channels or DMs for sensitive discussions
- Double-check data and dates in important announcements
- Use Slack's message editing feature for minor typos when appropriate

### When Deletion Makes Sense

Consider requesting deletion when:
- The message contains information that violates privacy policies
- Incorrect information could cause significant confusion or harm
- The message was clearly sent by mistake (wrong channel, accidental send)

### When Editing Is Better

Use Slack's built-in edit feature instead when:
- You just need to fix a typo or small error
- The correction doesn't change the meaning significantly
- The message is recent and hasn't been widely read yet
- Other context in the thread depends on the original message existing

## Privacy and Data Retention

### What's Stored in the Audit Log

For each deletion request, we store:
- The text content of the deleted message
- Channel name and message timestamp
- Your user ID and name
- Admin decision and who made it
- Date and time of all actions

### Why We Keep This Information

Audit logs serve important purposes:
- Regulatory compliance requirements
- Transparency in moderation decisions
- Protection against misuse of the deletion tool
- Reference for policy development and training

### Data Access

- Audit logs are accessible to workspace administrators
- Individual users can request information about their own deletion history
- Logs are retained according to our data retention policies

## Getting Help

If you have questions about:
- **Whether a deletion is appropriate:** Contact a workspace admin
- **Technical issues with the tool:** Report to the development team or workspace admin
- **Denied deletion requests:** Reach out to the admin who reviewed your request
- **Privacy concerns:** Contact your workspace administrator or privacy officer

## Remember

This tool exists to help you correct genuine mistakes while maintaining accountability and transparency in our workspace. Use it responsibly, and don't hesitate to ask an admin if you're unsure whether a deletion request is appropriate.

**When in doubt, ask first!**
